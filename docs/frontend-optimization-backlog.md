# Frontend smoothness & optimization backlog

## Context

Rahul (revisiting his college-era MERN project to bring it up to industry standard) asked for a full pass over `client/src` to list every modification that would make the app feel smoother/more optimized — a deliberate broadening of the same class of problem as the Seekbar fix (isolating re-renders, cutting unnecessary polling — see `client/src/Components/ControlArea/Seekbar.jsx`). This document is **an inventory to pick from**, not a single change to implement: the workflow is to review this list, pick one item (or a small cluster), implement it as its own scoped task with its own verification, and check it off here.

Three parallel audits were run (re-render/memoization, expensive-work/effect-hygiene, asset/CSS performance) covering every Context provider and every page/list component. Findings are deduplicated against `CLAUDE.md`'s backlog.

Originally drafted as a Claude Code plan-mode file; moved into the repo so progress is tracked alongside the code instead of in a local-only, non-versioned location.

## Tier 1 — small, isolated, high-impact (good next "one task" candidates)

1. ~~Memoize `PlaylistState.js` and `ShareState.js` context values~~ **Done**: Provider `value` wrapped in `useMemo` in both files, `handleshowPlaylistDialogue` (Playlist) and `share` (Share) wrapped in `useCallback`. All other exported functions in both files were already `useCallback`'d.
2. ~~Memoize `AlertState.js`'s context value~~ **Done**: `value={{ showAlert }}` now wrapped in `useMemo(() => ({ showAlert }), [showAlert])`; `hideAlert` (only used as a prop to the conditionally-rendered `AlertBox`, not part of the context value itself) wrapped in `useCallback` for consistency.
3. ~~Fix `Navbar.jsx`'s scroll listener~~ **Done** (commit `b8c9d66`): the handler is now named and gated behind `requestAnimationFrame` (via a `ticking` flag) instead of running unthrottled on every scroll pixel, and the effect now returns a proper `removeEventListener` cleanup, fixing the previous listener leak on remount.
4. ~~Fix `App.js`'s resize handler~~ **Done**: applied the same `ticking`/`requestAnimationFrame`-gating pattern used for the Navbar scroll fix — the 3 `setState` calls now run at most once per animation frame instead of once per native resize event.
5. ~~Fix `AlertBox.jsx`'s missing `setTimeout` cleanup~~ **Done** (commit `b8c9d66`): both timeout IDs are now stored and cleared in the effect's cleanup function, so an alert dismissed early (or a route change) no longer leaves a dangling timer that fires against an unmounted component. Added `?.` on the ref access as an extra safety net.
6. ~~Avoid the deep-clone hack on the hot playback path~~ **Done**: `play()` in `AudioState.js` now builds `song` via `{...tempSong, filePath: ..., coverImage: ...}` instead of `JSON.parse(JSON.stringify(tempSong))`.

## Tier 2 — medium effort, mostly mechanical

7. ~~Extract a shared `useNavbarHeight()` hook~~ **Done** (commit `e8b4a35`): replaces the ~12+ duplicated `document.querySelector(".navbar").offsetHeight` effects (`LoginPage`, `SignUp`, `HomePage`, `AllSongs`, `Artists`, `ParticularArtist`, `PlaylistMain`, `PlaylistDetails`, `SearchPage`, `LikedSongsPage`, `SongDetailsPage`, `ChatApp`) with `client/src/hooks/useNavbarHeight.js`. Also fixed a latent bug: the old effects used `[navbarHeight]` as their own dependency (self-referential, mount-only in practice); the hook properly re-measures on resize. `HomePage` no longer prop-drills `navbarHeight` to its four child sections.
8. ~~Extract a shared `useIsMobile()`/breakpoint hook~~ **Done** (commit `e8b4a35`): `client/src/hooks/useIsMobile.js` replaces the hardcoded `window.innerWidth < 1000` checks in `BottomControls`, `FullScreen`, `ChatApp`, `LikedSongsPage`, `Queue` — and, unlike the old inline reads, now stays live across resize instead of only updating on the next unrelated re-render.
9. ~~Fix `ChatApp.jsx`'s per-message layout read~~ **Done** (commit `e8b4a35`): added `client/src/hooks/useElementHeight.js`, used in place of the inline `chatAppContainer?.current?.offsetHeight` reads — the container height is now only re-measured on mount/resize, not on every incoming/outgoing message.
10. ~~Guard against redundant re-fetching on remount~~ **Done** (commit `dca4bca`): `fetchSongs`/`newReleaseFunc`/`oldReleaseFunc` (`SongState.js`) and `fetchArtists` (`ArtistState.js`) now cache their no-search-term result in a ref; `getPublicPlaylist` (`PlaylistState.js`) got an opt-in `useCache` flag (default off, so `PlaylistMain`/`PlaylistDetails` still always fetch fresh) that only `UrbanPunjabiTadka`/`WestTunes` pass.
11. ~~`React.memo` pass on `SongCardXL`/`SongCardMedium`~~ **Done** (commit `15c583e`): both wrapped in `React.memo`, and the inline `wrapperProps`/style object literals (`Queue.jsx`'s `style={{ textWrap: "wrap" }}`, both cards' `LazyLoadImage` `wrapperProps`) hoisted to module-level constants so they don't defeat the memoization with a fresh object every render.
12. ~~Extract a shared `ArtistCard` component~~ **Done** (commit `15c583e`): `client/src/Components/Artists/ArtistCard.jsx` replaces 4 byte-identical duplicates (2x `Artists.jsx`, 2x `SearchPage.jsx` — the latter's array-vs-single-object branch collapsed into one `.map()`). Built with `LazyLoadImage` from the start.
13. ~~Roll out `LazyLoadImage`~~ **Done** (commit `15c583e`): applied to `ParticularArtist.jsx`, `BottomControls.jsx`, `FullScreen.jsx`, `CurrPlaylist.jsx`, `Queue.jsx`'s network image, `SongDetailsPage.jsx`, `ChatArea.jsx`, `UserProfileButton.jsx`, plus both `ArtistCard` call sites. Deliberately skipped `PlaylistMain.jsx`'s two `<img>` tags — `Playlist` has no `thumbnail` field in the backend schema, so both currently always resolve to the bundled static logo (no network image ever loads there); same reasoning as skipping the static `PlayingBarGif` asset in `Queue.jsx`/`ParticularArtist.jsx`/`SongDetailsPage.jsx`. Explicit `width`/`height` attributes were not added — deferred, since CLS risk was already assessed as low (most containers have fixed CSS sizing).

## Tier 3 — bigger, needs more design/testing before committing

14. ~~Route-level code splitting~~ **Done** (commit `31bb7b8`): every route except `Home` ("/") is now `React.lazy` + `Suspense`-wrapped. Verified via build output: main bundle gzipped ~133kB → ~80kB, rest split into ~20 on-demand chunks.
15. ~~Replace or lazy-load `react-beautiful-dnd`~~ **Done** (commit `5862e5a`): did both — swapped to the maintained, API-identical `@hello-pangea/dnd` fork (import-path-only change in `Queue.jsx`/`CurrPlaylist.jsx`), and lazy-loaded both components with `Suspense` boundaries in `FullScreen.jsx`/`PlaylistDialogue.jsx` so the DnD chunk only downloads when the queue or a playlist is actually opened. **Recommend a manual drag-and-drop smoke test** (reordering the queue and a playlist) — this is the one change in this batch touching third-party library behavior, not just internal code.
16. ~~Video asset handling~~ **Partially done, rescoped** (commit `f3df9a4`): replaced the `isMobile`-computed `<video src={...}>` ternary with two native `<source media="...">` elements — the browser now picks and downloads only the matching variant itself. Re-encoding/compressing the videos or adding poster frames is still out of scope (no video-editing tooling available in this environment); the "both ship in build output" concern is also inherent to having two responsive variants at all, not a bug per se.
17. ~~`FullScreen`'s open-transition jank~~ **Done, needs visual QA** (commit `d6eaa1a`): `@keyframes fullscreen-entry-anime` now animates only `transform` (`translateY` + `scale`) instead of `border-*-radius`/`top` alongside it. Same intended visual (grows open from the bottom), but not verified in a browser — check the fullscreen open animation before fully trusting this.
18. ~~`HomePage.css`'s infinite background animation~~ **Done, needs visual QA — riskiest change in this batch** (commit `d6eaa1a`): moved the background off `.homeContainer` itself (a class shared by ~8 different page containers, not just Home) onto a `::before` pseudo-element sized 200% wide, panned via `transform: translateX` instead of animating `background-position`. The `background-size`/position math translating from the original percentage-based approach to the pseudo-element's dimensions is the part I'm least certain about pixel-for-pixel — **check every page using the `.homeContainer` class**, not just the actual Home page.
